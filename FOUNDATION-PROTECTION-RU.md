# P04 — защита неподтверждённого основания

Состояние на 20.10.2026: известная реализация P04 и сверка фоновых обработчиков завершены по исходникам, игровые проверки отложены. Итог — FOUNDATION-NPC-RU.md, платный путь — FOUNDATION-PAYMENTS-RU.md.

FoundationCreationProtection устанавливает SQL-триггеры для текущей схемы после инициализации сервисов, до игровых тиков. Они блокируют INSERT/UPDATE/DELETE, затрагивающие записанные в CREATING ID лагеря, города, цивилизации и здания. Учитываются первичные записи, объявленные внешние ключи и принятые имена ссылочных колонок camp/town/civ/build. Изменение членства основателя также блокируется; обычное обновление его имени при входе не блокируется. UPDATE без изменения значений пропускается.

Это постоянные триггеры БД, поэтому защита действует и через отдельные соединения лагерного сервиса и API. На игровых соединениях записи включён recursive_triggers: скрытое удаление конфликтующей строки в INSERT OR REPLACE тоже проходит DELETE-защиту. Проверка всех затронутых правил SQL и существующих триггеров входит в V01/V04; компиляция не доказывает их игровую корректность.

Создание записей, подтверждение и компенсация получают разрешение REGISTER/COMMIT/ROLLBACK только внутри соответствующей SQL-транзакции. Разрешение удаляется до commit; при ошибке оно откатывается вместе с транзакцией. Разрешение не должно переживать отдельное сохранение и не используется для обычных команд. Метаданные самого журнала исключены из автоматически создаваемых защитных триггеров.

Перед начальной миграцией схемы, пока игровой код плагина ещё не запущен, прежние защитные триггеры снимаются. После инициализации таблиц они строятся заново для текущей схемы. Изменение конфигурации или миграции в этой фазе может изменить снимок временной записи; такой результат удерживается для сверки вместо удаления по старому снимку. Это не защита от стороннего редактирования SQLite и не обещание неизменности записей при миграции схемы.

Из периодической обработки исключены временные города/лагеря в следующих местах:

- Минутный доход, часовая культура и накопление неиспользованной науки, расчёт регионов культуры.
- Начальное выделение земель TownLimitsStore, план содержания, налоговые начисления и срок до выселения, банковские проценты.
- Общий обход лагерей и выбор лагерей для просеивания.

Налоги и выселение также пропускают основателя в CREATING, чтобы неоднозначная операция не прерывала общий расчёт. Основные игровые команды основателя/участника временного поселения завершаются русским сообщением до выполнения действия; административная диагностика остаётся доступной.

Общие подсчёты, рейтинги, победы, правительства и доход чудес дополнены фильтрами; карта и условия исключения по COMPLETE описаны в FOUNDATION-BACKGROUND-RU.md. Для ссылок kind+ID у приглашений и журнала содержания добавлены явные правила. Военный результат, меняющий временные связи, ждёт целиком, сохраняя победителей для повторного прохода. Собственные таймеры NPC/вспомогательных служб и их восстановление сверены в FOUNDATION-NPC-RU.md; найденные обходы исправлены. Неучтённая запись через защищённую связь отклоняется SQL и может задержать вызывающий пакет: новые пути, выявленные A03 или игровыми проверками, потребуют исправления, а не объявления успешного восстановления. Новые таблицы после установки защиты требуют обновления правил. Платный путь реализован отдельно с явной сверкой внешних результатов.

Чистая сборка 339 Java-исходников с -Dmaven.test.skip=true успешна. Тесты, запуск Paper и обновление серверного JAR не выполнялись; старый сервер не изменялся.
