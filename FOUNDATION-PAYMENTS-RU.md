# P04 — оплата и возврат основания

Состояние на 20.10.2026: реализация до тестов. Это оплата прежнего административного основания города через выдаваемый предмет. Настоящий поселенец, лагерь и основание цивилизации не получают повторной личной платы: их fee остаётся нулевым.

FoundationPaymentStore записывает сумму, UUID, режим LOCAL/VAULT, имя провайдера и валюту вместе с переходом основания в CREATING. Сумма проверяется как целое положительное число, точно представимое в используемом double. Создание города через этот путь требует подтверждённой квитанции и больше не вызывает прежнее отдельное списание townCost. Подтверждение всей операции проверяет квитанцию по БД, а не флаг успешного ответа в памяти.

## Местные монеты

Списание с residents.coins и запись PAID выполняются в транзакции подготовки плана. Недостаток денег откатывает и списание, и переход в CREATING. Если полностью зарегистрирована очередь, восстановление подтверждает основание без повторного списания. Если очереди нет и записи поселения неизменны, компенсация удаляет их, восстанавливает членство, прибавляет исходную сумму, записывает REFUNDED и запрашивает возврат предмета одной транзакцией. Переполнение баланса останавливает транзакцию. Смена настроек на Vault не переносит возврат местных денег во внешний провайдер.

## Внешний Vault

Vault не предоставляет общей транзакции с SQLite и ключа идемпотентности для этих вызовов. Перед внешним действием отдельно сохраняется CLAIMED или REFUND_CLAIMED. Совпадение имени провайдера и валюты проверяется перед отправкой; недоступный/сменившийся провайдер не подменяется местным балансом. Имя провайдера не является доказательством неизменности его внутреннего хранилища.

| Стадия | Обработка |
|---|---|
| WAITING | Вызов списания ещё не отправлен; при прерванном основании можно отменить без возврата денег. |
| CLAIMED | Списание отмечено отправляемым; при потере ответа автоматически не повторяется. |
| PAID | Положительный ответ сохранён; можно создавать/подтверждать поселение. |
| DECLINED | Провайдер вернул отрицательный ответ списания; основание отменяется без денежного возврата. |
| CANCELLED | Отменено до отправки списания. |
| REFUND_PENDING | Поселение компенсировано; ожидается отправка возврата исходному провайдеру/валюте. |
| REFUND_CLAIMED | Возврат отмечен отправляемым; потерянный ответ требует сверки. |
| REFUND_FAILED | Провайдер отрицательно ответил на возврат; автоматического повтора нет. |
| REFUNDED | Положительный ответ возврата сохранён; можно запрашивать возврат предмета. |

Исключение вызова, пустой ответ или потерянное подтверждение SQLite оставляют CLAIMED/REFUND_CLAIMED. Состояние до вызова может быть сохранено, даже если процесс завершился непосредственно перед обращением к провайдеру; это тоже требует сверки, а не догадки по текущему балансу. Отрицательный ответ обрабатывается по контракту Vault как отклонённая транзакция. Неоднозначный результат не объявляется гарантией однократного внешнего действия.

Отмена частичного платного основания сохраняет удаление/обратное членство и REFUND_PENDING вместе. Деньги возвращаются OfflinePlayer, присутствие игрока не требуется. Сам предмет остаётся в резерве до подтверждённого денежного возврата; затем используется общий журнал инвентаря, курсора и переполнения. Квитанция компенсации предотвращает повторное удаление поселения. Для полностью зарегистрированной и оплаченной очереди восстановление завершает основание вместо возврата.

## Сверка администратором

`/civadmin recovery status` показывает стадию основания и оплаты. Подробности:

`/civadmin recovery payment <ID основания> status`

После проверки фактической операции в журнале внешнего провайдера администратор с прежним правом civcraft.admin записывает одно решение:

- `charged` — для CLAIMED подтверждено списание: сохранить PAID.
- `notcharged` — для CLAIMED подтверждено отсутствие списания: сохранить DECLINED.
- `refunded` — для REFUND_CLAIMED/REFUND_FAILED подтверждён возврат: сохранить REFUNDED.
- `refundnotpaid` — для REFUND_CLAIMED/REFUND_FAILED подтверждено отсутствие возврата: снова разрешить одну отправку из REFUND_PENDING.

Решение меняет только подходящую стадию внешней квитанции, сохраняет актёра, прежнюю/новую стадию и время в foundation_payment_resolutions. Оно не создаёт поселение, не выдаёт предмет и не подтверждает весь журнал напрямую. Дальнейшие действия выполняет обычное восстановление. Команда не проверяет журнал провайдера вместо администратора.

Старые платные CREATING без квитанции удерживаются: прошлое отдельное списание не восстанавливается из текущего баланса и не повторяется. Нулевые старые планы сохраняют прежнюю проверку записей/очереди. Повреждённые или несовместимые записи требуют отдельной сверки.
