# P04 — сохраняемый план основания

Состояние на 20.10.2026: реализация до игровых проверок. P04 остаётся открытым.

FoundationCreationStore сохраняет план вместе с переходом RESERVED → CREATING: UUID и вид основания берутся из резерва, записываются имена, тег, шаблон, нормализованный поворот, координаты постройки и первоначальной позиции игрока, стоимость административного пути и исходное членство жителя.

ID лагеря, цивилизации и города записываются в план внутри соответствующей транзакции создания. Настоящий поселенец использует тот же механизм через SettlerTownStore. Несовпадение создаваемой записи с открытым планом вызывает отказ транзакции; повторная привязка другого ID запрещена. ID остаются в плане даже при удалении объекта, чтобы отсутствие записи не считалось доказательством отсутствия попытки создания.

Оба формата строительной очереди используют recordPreparedStructureBuild: запись здания, занятые чанки, привязка ID и build_ready сохраняются одной транзакцией. BuildQueue проверяет разрешение до загрузки чанков, снимка местности, контура и установки блоков. Незавершённое основание удерживает очередь. При ошибке после регистрации такая очередь не удаляется обычным обработчиком отката постройки. Существующая процедура перезапуска ставит неначатую очередь заново; неожиданное сочетание неподтверждённого плана с готовым снимком мира удерживается для сверки.

commitReady сверяет реальные записи, владельцев, имена, координаты, цивилизацию города, параметры и статус очереди и членство жителя. Для настоящего поселенца перенос из прежнего города, начальный чанк и COMMITTED выполняются одной транзакцией. Для столицы и административного города начальный чанк тоже создаётся или проверяется в этой транзакции. Повторное подтверждение уже COMMITTED ничего не меняет. Неясный ответ SQL не запускает прежнее удаление объектов по ссылкам из памяти.

При запуске и затем периодически обработчик пытается подтвердить полностью зарегистрированные планы с нулевой дополнительной платой. Ошибка одного резерва не прерывает обработку остальных. Пустой бесплатный план допускает отмену только при отсутствии всех привязанных ID и точном совпадении исходного членства; возврат предмета остаётся операцией общего журнала инвентаря. Это не повторное создание поселения и не автоматическое согласие главы: восстанавливается уже принятое подтверждение.

## Отмена частично созданного поселения

FoundationCreationRollback сохраняет контрольные суммы полных строк лагеря, цивилизации и города в транзакции их создания, а для лагеря — также исходное членство. Снимок учитывает имена столбцов, границы и типы значений. До изменения членства сохраняются долг, дни до выселения и прежняя запись ожидания повторного вступления.

Для бесплатного CREATING без зарегистрированной очереди восстановление сверяет снимки, точное текущее членство и ссылки на созданные ID. Проверяются объявленные внешние ключи и принятые в схеме имена колонок camp/town/civ; посторонние жители, здания, участки и другие связанные записи останавливают компенсацию. Старые планы без снимков и изменившиеся записи не удаляются. Сверка неизвестных способов ссылаться на поселения остаётся частью A03 и проверки защиты временных объектов.

При совпадении удаляются только записанные в плане поселения и исходная запись участника лагеря. Прежнее членство, квитанция компенсации и CANCEL_REQUESTED сохраняются вместе с удалением в одной транзакции. Ссылки на созданные ID остаются в плане; отмену при наличии таких ссылок разрешает квитанция успешной компенсации. Возврат предмета выполняется прежним общим журналом, не прямой выдачей. Повторная обработка квитанции не повторяет удаление.

Если поселенец ещё не сменил город, обновление членства не выполняется: прежние участки, налоги и помощник не затрагиваются. При отмене нового города административного/столичного пути перед обратным переходом проверяется неизменность налогового состояния, а созданные триггерами побочные изменения долга и ожидания повторного вступления компенсируются исходным снимком. Изменившиеся данные удерживают операцию вместо перезаписи.

Известная синхронная ошибка запускает сверку сразу после удаления диалога, до следующего игрового тика; после перезапуска используется тот же обработчик. Начальное определение столицы пропускает неподтверждённые новые цивилизации, чтобы не изменять их снимок до решения журнала. При успешном подтверждении столица записывается вместе с COMMITTED.

Платный административный путь теперь использует FoundationPaymentStore: местное списание связано с подготовкой плана, местный возврат — с компенсацией. Внешний Vault имеет отдельные стадии отправки/ответа и сверку неопределённого результата. Восстановление готового платного плана проверяет квитанцию; частичное основание компенсируется только при определённом результате списания. Подробности — FOUNDATION-PAYMENTS-RU.md.
