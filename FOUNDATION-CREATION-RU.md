# P04 — сохраняемый план основания

Состояние на 20.10.2026: реализация до игровых проверок. P04 остаётся открытым.

FoundationCreationStore сохраняет план вместе с переходом RESERVED → CREATING: UUID и вид основания берутся из резерва, записываются имена, тег, шаблон, нормализованный поворот, координаты постройки и первоначальной позиции игрока, стоимость административного пути и исходное членство жителя.

ID лагеря, цивилизации и города записываются в план внутри соответствующей транзакции создания. Настоящий поселенец использует тот же механизм через SettlerTownStore. Несовпадение создаваемой записи с открытым планом вызывает отказ транзакции; повторная привязка другого ID запрещена. ID остаются в плане даже при удалении объекта, чтобы отсутствие записи не считалось доказательством отсутствия попытки создания.

Оба формата строительной очереди используют recordPreparedStructureBuild: запись здания, занятые чанки, привязка ID и build_ready сохраняются одной транзакцией. BuildQueue проверяет разрешение до загрузки чанков, снимка местности, контура и установки блоков. Незавершённое основание удерживает очередь. При ошибке после регистрации такая очередь не удаляется обычным обработчиком отката постройки. Существующая процедура перезапуска ставит неначатую очередь заново; неожиданное сочетание неподтверждённого плана с готовым снимком мира удерживается для сверки.

commitReady сверяет реальные записи, владельцев, имена, координаты, цивилизацию города, параметры и статус очереди и членство жителя. Для настоящего поселенца перенос из прежнего города, начальный чанк и COMMITTED выполняются одной транзакцией. Для столицы и административного города начальный чанк тоже создаётся или проверяется в этой транзакции. Повторное подтверждение уже COMMITTED ничего не меняет. Неясный ответ SQL не запускает прежнее удаление объектов по ссылкам из памяти.

При запуске и затем периодически обработчик пытается подтвердить полностью зарегистрированные планы с нулевой дополнительной платой. Ошибка одного резерва не прерывает обработку остальных. Пустой бесплатный план допускает отмену только при отсутствии всех привязанных ID и точном совпадении исходного членства; возврат предмета остаётся операцией общего журнала инвентаря. Это не повторное создание поселения и не автоматическое согласие главы: восстанавливается уже принятое подтверждение.

Остаток P04:

- Компенсация частично созданного лагеря, цивилизации или города, когда полностью зарегистрированной очереди ещё нет; доказательство неизменности объектов перед удалением и восстановление исходного членства.
- Защита таких временных объектов от фоновой экономики и других действий до результата восстановления.
- Сохраняемое подтверждение списания/возврата платного административного основания; неопределённый результат внешнего Vault нельзя считать ни успешным, ни безопасным для повтора.
- Сверка старых CREATING без плана и обработка отсутствующей/повреждённой очереди. Эти случаи сейчас удерживаются без автоматического возврата предмета.

Изменения компилируются с пропуском тестов. Игровая проверка, сценарии прерывания и установка нового JAR ещё не выполнялись. Старый сервер не изменялся.
