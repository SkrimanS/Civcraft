# P04 — фоновые расчёты и временные поселения

Состояние на 20.10.2026: сверка по исходникам, без запуска тестов/Paper. Известная реализация P04 завершена; дополнение по NPC — FOUNDATION-NPC-RU.md.

Основание может оставить город или цивилизацию в БД до подтверждения очереди. Одной блокировки записи недостаточно: временный город меняет общие суммы, даже когда результат записывается совсем другому поселению. Поэтому выборки должны исключать именно created_* из CREATING, сохраняя обычную обработку прежнего города/цивилизации поселенца.

| Область | Реализованное исключение / доказательство по коду |
|---|---|
| Доход, налоги, содержание, проценты | Фильтры входных городов и лагерей добавлены ранее. Дополнительно UpkeepStore пропускает временные записи в общем обновлении days_in_debt. |
| Количество городов и счастье | civTownCount, townCount, townBaseProductions и внутренние COUNT/MIN в townMood исключают временные города. Они не добавляют имперское несчастье существующим городам. |
| Исследования | activeResearches исключает временные цивилизации; расчёт суммарной науки существующей цивилизации использует отфильтрованные townBaseProductions. |
| Правительства | Переходы временных цивилизаций, очереди/города при retimeData, refreshQueuedProduction и население для длительности анархии исключены из общих выборок. |
| Рейтинги | LegacyScoreStore не пересоздаёт/не показывает рейтинг временной цивилизации. RevolutionRules.civilizationScore не считает временные города существующей цивилизации. |
| Победы | EndGameStore фильтрует кандидатов, общую долю завоевания, культурные города/чудеса, соперников по колбам/голосам и итоговый снимок очков. Неподтверждённая цивилизация не допускается к meets. При голосовании проверяются актёр и цель до записи ожидания повторного голосования. Текущие таблицы вывода используют те же ограничения; сохранённый финал раунда не переписывается. |
| Доход чудес | Мировое число городов для Колизея и число мирных городов для Нотр-Дама исключают временные записи; выбор источников и культурных участков также фильтруется. При поиске целей Колосса временные города не участвуют в расстояниях и временные цивилизации не занимают место цели. |
| Активность зданий | BuildingActivityService.reconcile пропускает временные здания/города и не регистрирует их в structure_activity до подтверждения. |
| Проверка опоры | HallValidationService пропускает временную очередь при подборе геометрии и временное здание при автоматической проверке. |
| Производство, содержание существ, регенерация, контрольные точки, возрождение у ратуш | Проверенные входные выборки используют COMPLETE/active_structure_builds и подходящие типы завершённых зданий. Новое CREATING не может попасть в COMPLETE: BuildQueue ждёт COMMITTED перед первым изменением мира и завершением. Это доказательство для новых корректных журналов; повреждённые старые сочетания не считаются безопасными автоматически. |

## Применение военных результатов

ConquestStore перед применением любой части конкретного результата проверяет временные поселения и основателей, чьё членство затронет перенос города/поражение цивилизации. Такой результат целиком остаётся в очереди: war_results не заполняется, флаги победителей сохраняются, остальные результаты войны продолжают обрабатываться. Повторный проход выполнит перенос после восстановления основания. Временный город не выбрасывается из списка захваченных городов с одновременной отметкой «всё применено».

Это согласование восстановления, а не изменение правил победы/захвата в обычной игре. Пока CREATING не разрешён, прямые действия, нарушающие замороженные связи, по-прежнему могут быть отклонены SQL-защитой.

## Ссылки без внешних ключей

Помимо внешних ключей и принятой схемы имён колонок добавлены общие TaggedReference-правила:

- settlement_invites: kind=CIV/TOWN и settlement_id.
- upkeep_payments: kind=civ/town и target_id.

Правила используются и SQL-защитой INSERT/UPDATE/DELETE, и проверкой отсутствия посторонних данных перед компенсацией. Числовой ID не сравнивается с другим видом поселения без проверки kind.
